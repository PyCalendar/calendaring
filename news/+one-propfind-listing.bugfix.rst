On CalDAV, ``collections()`` no longer sends one PROPFIND per calendar for its component set, where caldav keeps the listing's properties (after 3.7): 469 calendars on a Synology took 268 s, the listing alone 6 s.  With caldav 3.7, or a server whose listing leaves the component set out, each calendar is still asked; so is each on a server whose listing names calendars that are not there (Bedework 5, by caldav's ``propfind.listed-members-exist`` hint), to leave those out.  That takes caldav's Bedework 5 profile (``features: bedework_5_0_0``): without hints, Bedework 5's ghost ``tasks/`` is listed.
