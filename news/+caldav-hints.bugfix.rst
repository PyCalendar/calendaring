The CalDAV backend now declares what caldav's hints already record: a task list on Ox stores no attendees, recurrences or X- properties (so no planned times), Ox and Zimbra drop ``ESTIMATED-DURATION``, and Zimbra renames every object to ``<uid>.ics``, so ``identity.client-native-id`` is unsupported there.  Where the server keeps ``RELATED-TO`` but refuses an event holding a ``PARTICIPANT`` (CCS, GMX), ``time-log`` is ``lossy`` with ``users`` lost, and entries are written without their users instead of being refused.
