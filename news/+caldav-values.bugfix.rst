With a caldav whose hints record them, the CalDAV backend declares the ``STATUS`` and ``PRIORITY`` values a server's task lists keep (Ox: priorities 1, 5 and 9, and no ``PENDING`` or ``FAILED``; Zimbra: no ``CANCELLED``), ``write.wire`` unsupported where X- parameters are dropped, and ``identity.client-native-id`` unsupported in Ox task lists.  On Zimbra, whose calendar-multiget still returns deleted objects, an object is read with a GET.  ``PRIORITY:0`` is left out rather than stored as another priority.  The conformance suite's ``test_values_map_as_declared`` no longer adds one item twice, which failed on a backend keeping the client's UID.
