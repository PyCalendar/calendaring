New conformance-suite hook ``reuses_collections()``: a backend that limits how many collections may be made in a while overrides it to return ``True``, and the suite then keeps each collection it makes and uses it again, as it already did where collections cannot be deleted, rather than make one per test.  The test of making and deleting a collection still makes one per run, and the first run on an account makes a few more.  The CalDAV tests turn it on where caldav's ``rate-limit`` hint gives ``create_calendar_per_hour`` (ecloud, which refuses calendar creation after about 10 an hour).
